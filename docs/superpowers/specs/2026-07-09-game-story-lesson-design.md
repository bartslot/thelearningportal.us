# Game Story Lesson ("Spel-verhaal") — Design Spec

**Date:** 2026-07-09
**Status:** Draft (brainstorm output — method + integration options)
**Context:** Builds on `2026-06-19-story-configuration-narrative-spine-design.md` (branching lite) and the 2026-07-08 gamification brainstorm (Bart × Michiel, transcript: `~/Downloads/brainstorm-gamification-transcript.md`). Related: Epic K modules (`app/Enums/ModuleType.php`), LessonTeam strategy games.

## 1. Goal

Turn the one-shot "Branching story" arc into a full **game story lesson**: a lesson where game mechanics are woven through the entire narrative — repeated choice points, class-state meters, an AI game master, and optional printed game cards (PDF) for physical classroom play. The story stays historically true; the *game* is how the class navigates it.

Why: the brainstorm surfaced that choice + consequence + physical participation is what makes a class lesson feel like a game, and the current system already has 80% of the data model for it.

## 2. Method — the four mechanics from the brainstorm

| # | Mechanic | Brainstorm source | Core rule |
|---|----------|-------------------|-----------|
| M1 | **Illusion of choice, historical spine** | "alles wat langskomt echt gebeurd laten blijven, maar telkens de illusie van keuze" (14:59) | Every choice point offers plausible options; whichever is chosen, the story reconverges to what really happened. Consequences are expressed in *meters and narration*, never in counterfactual history. |
| M2 | **State meters (Reigns mechanic)** | "vier meters… elke keuze zorgt dat één omlaag of omhoog gaat; eentje beneden peil = af" (11:42–12:13) | The lesson defines 3–4 topic-specific meters (e.g. Napoleon: *Moreel, Manschappen, Voorraden, Steun*). Each choice option carries meter deltas. Any meter hitting zero = class "loses the run" (roguelike: survive to the end of the story). |
| M3 | **AI as Dungeon Master / judge** | "AI als de Dungeon Master… bepaalt wie er gelijk heeft of de beste creatieve oplossing" (2:55, 4:15) | The AI narrates the consequence of each choice and (v2) judges free-text class answers on creativity + historical plausibility. v1 is pre-generated and deterministic; v2 is live. |
| M4 | **Whole-class physical play** | "manschappen verliezen = kinderen gaan zitten; dokterkaart maakt iemand levend; wie dood is moedigt aan" (4:56–5:20) | The class *is* the army/faction, organized in **teams of 3–4** (existing `LessonTeam`). Printed role cards are held by *teams, not individual students* — the Dokter-team, the Verkenner-team, etc. Losing meter points costs teams "manschappen tokens"; a team that runs out sits out one round (and cheers the others on). Teams take turns making the call. **Teacher feedback (Alfonso, IT history teacher, 2026-07-09): assigning special roles to individual kids singles them out and is socially unacceptable in practice; roles per group of 3–4 removes that problem entirely.** |

The method in one sentence: **a branching-lite story with N choice points, where choices move meters instead of rewriting history, an AI game master narrates consequences, and printed cards map the game onto real children in a real classroom.**

## 3. Decisions (proposed)

| Topic | Decision |
|-------|----------|
| New lesson type vs. extension | **Extension, not a fork.** No new `lesson_type` column. A game story lesson = `narrative_framework = branching` + new `game_type = 'story_game'`. All wizard, pipeline, player and results infrastructure is reused. |
| Number of choice points | Extend branching lite from 1 to **3–5 branch groups** (one per act). `scenes.branch_group` is already an integer and the player already keys choices per group — this is a generation-prompt + UI change, not a schema change. |
| Story divergence | **None.** Both options in a group reconverge (existing pattern). Divergence lives in meters + one AI-narrated consequence line per option. Guards the no-hallucination policy: the spine is always the real history. |
| Meters | Lesson-level config (4 max), generated by the outline prompt from the topic, editable by teacher in Step 3. Deltas per choice option stored on the option scene. |
| Game over | Meter at 0 → "game over" interstitial ("Zo liep de geschiedenis bijna anders…") + restart-from-act option. Never blocks finishing the lesson content: teacher can override-continue. |
| AI judging | **v1: pre-generated** (deltas + consequence text at build time, offline, cheap, deterministic). **v2: live judge** for free-text class answers via LLM with rubric (creativity, historical plausibility), same guardrail style as map-quiz AI assist (LLM writes text, never facts). |
| Physical layer | **Printed PDF pack per lesson** (see §6): role cards, event cards, meter tracker poster, team badges. Optional — the lesson plays fully digital without it. |
| PDF engine | `barryvdh/laravel-dompdf` (pure PHP, works on SiteGround shared hosting; Browsershot needs headless Chrome — not available there). Blade templates → PDF. |
| Class mode | Reuse `LessonTeam` (auto-formed, 3–4 students per team). Teams alternate as "decision maker" per branch group; rest of class votes advisory. Solo/Flutter mode: student decides alone, same data. |
| Role granularity | **Roles belong to teams, never to individual students.** Alfonso (pilot-adjacent IT history teacher): per-kid roles make kids feel treated differently and fail in practice; per-team roles (3–4 kids) are socially safe and self-moderating. All physical mechanics (roles, tokens, sitting out) operate at team level. |

## 4. Data model

### 4.1 Lesson

```php
// lessons table — no new columns needed beyond:
'game_type' => 'story_game'   // new enum value next to quiz | strategy | debate
'game_config' => json          // NEW nullable column (or reuse existing config pattern)
```

```json
// lesson.game_config
{
  "meters": [
    { "key": "morale",   "label": "Moreel",      "icon": "ti-flame",  "start": 70 },
    { "key": "troops",   "label": "Manschappen", "icon": "ti-users",  "start": 100 },
    { "key": "supplies", "label": "Voorraden",   "icon": "ti-package","start": 60 },
    { "key": "support",  "label": "Steun",       "icon": "ti-heart",  "start": 50 }
  ],
  "fail_threshold": 0,
  "team_turns": true,
  "print_pack": true
}
```

### 4.2 Scene (choice options)

Branch columns unchanged. Add per-option effects in the existing `scenes.config` JSON (no migration):

```json
// scene.config for a branch option scene (branch_role = option_a)
{
  "branch_effects": {
    "deltas": { "morale": +10, "troops": -15, "supplies": 0, "support": +5 },
    "consequence_line": "De cavalerie breekt door, maar de modder eist zijn tol — vijftien man keert niet terug.",
    "historical_note": "Napoleon stelde de aanval in werkelijkheid uit tot de grond droger was."
  }
}
```

### 4.3 Progress

`student_progress.answers` JSON gains a `game` key (no migration; column is already JSON):

```json
{
  "game": {
    "choices": { "1": "option_a", "2": "option_b" },
    "meters_final": { "morale": 45, "troops": 60, "supplies": 20, "support": 75 },
    "survived": true,
    "restarts": 1
  }
}
```

Meters double as a score: `survived` + average meter level → existing score/max_score contract stays intact for the results hub.

## 5. Player UI & flow

```
┌──────────────────────────────────────────────────────┐
│ ▓▓▓▓▓░░ Moreel   ▓▓▓▓▓▓▓ Manschappen  ▓▓▓ Voorraden │  ← meter HUD (Reigns-style)
│                                                      │
│              [ scene image / skybox ]                │
│                                                      │
│  ┌────────────────────────────────────────────────┐  │
│  │  Napoleon aarzelt. De verkenners melden…       │  │  ← narration (existing)
│  └────────────────────────────────────────────────┘  │
│                                                      │
│   ┌──────────────────┐   ┌──────────────────┐        │
│   │ Stuur de         │   │ Wacht tot de     │        │  ← existing choice overlay
│   │ cavalerie  ⚔️     │   │ grond droogt ⏳  │        │     + meter-delta hints (optional)
│   └──────────────────┘   └──────────────────┘        │
└──────────────────────────────────────────────────────┘
```

1. Meter HUD renders from `lesson.game_config.meters`; animates deltas after each choice (bar pulse + floating +10/−15).
2. Choice overlay = existing branch overlay; after the chosen option scene plays, the `consequence_line` is shown as a game-master caption (distinct styling: parchment/DM voice), then the story reconverges.
3. Meter at 0 → game-over interstitial with `historical_note` ("wat er echt gebeurde"), restart-from-act button, teacher override-continue.
4. End screen: run summary (choices made, final meters, survived y/n) → feeds the same progress POST.
5. Classroom projection mode: teacher plays on the beamer; "whose turn" banner shows the active `LessonTeam`; voting happens physically (or v2: student devices).

## 6. Printed game pack (PDF)

Generated per lesson from Blade templates via dompdf; downloadable in Step 4 / lesson detail as one PDF:

| Sheet | Contents | Ties into |
|-------|----------|-----------|
| **Team role cards** (A5, one per team) | Commandant-team (makes the final call this round), Verkenner-team (may peek at one delta hint), Dokter-team (restore one lost manschappen-token), Spion-team (swap one option once), Boodschapper-team (reads the consequence aloud) | M4; roles are per team of 3–4, never per individual student (Alfonso feedback); generated per topic by AI (title + flavor text + power), teacher-editable; card count = `team_count` |
| **Manschappen tokens** (sheet of ~20, cut lines) | Physical tokens per team representing troop strength; meter losses = tokens handed in; team at 0 sits out one round and cheers | M2 + M4 |
| **Event cards** | One per branch group: the choice question + both option texts (for offline play without screen) | M1 |
| **Meter tracker poster** (A4/A3) | 4 meter tracks with checkbox steps; magnets/whiteboard-friendly | M2 |
| **Team badges** | Team name + color from `LessonTeam` | class mode |
| **Answer sheet** (optional, v2) | Numbered-mode choice bubbles per act — compatible with the existing paper-import vision flow (`DevPaperSheet` pattern) so a photographed sheet can be scanned back into progress | paper import |

New service: `GameCardPdfService` (`app/Services/`), new job `GenerateGamePack` appended to the pipeline batch when `game_config.print_pack = true`.

## 7. Generation pipeline changes

1. **StorySpine**: new spine for story_game — `['Setup', 'Choice', 'Consequence', 'Choice', 'Consequence', 'Choice', 'Climax', 'End']` (3 branch groups), `gamePlacementBeat` obsolete (game is everywhere).
2. **LessonOutlinePrompt**: when `game_type=story_game`, additionally generate: `meters[]` (topic-fitting, Dutch labels), per-option `deltas` + `consequence_line` + `historical_note`, and 4–6 `roles[]` for the card pack. Hard rule in prompt: *options may differ in approach, never in outcome — history stays true* (reuses the no-hallucination system prompt).
3. **BuildLessonOutline**: persist meters/roles into `lesson.game_config`, effects into `scene.config.branch_effects`.
4. **GenerateGamePack** (new, optional): render PDF pack, store `game_pack_path` on lesson.

## 8. Teacher authoring (Step 2 + 3)

- **Step 2 Story**: selecting arc "Branching story" now shows a sub-toggle: *Eén keuzemoment* (current) / *Spel-verhaal* (full game). Choosing Spel-verhaal sets `game_type=story_game` and shows a one-line explainer + print-pack checkbox.
- **Step 3 Configure**: inspector for a branch-option scene gains a "Game effects" panel: 4 delta steppers, consequence line, historical note. Lesson-level "Meters" panel (rename labels/icons, start values). "Download spelpakket (PDF)" button after generation.
- Validation: deltas within ±25; every branch group must have both options' effects filled before publish.

## 9. Testing strategy

- **Pest**: meter math (deltas, clamp 0–100, fail detection), outline persistence of game_config/branch_effects, progress payload with game key, PDF service renders non-empty PDF per sheet type.
- **Playwright**: play a 3-choice story_game lesson end-to-end — choose, see delta animation, hit game over deliberately, restart, finish, verify progress POST.
- **Prompt eval** (manual first): 5 topics × outline generation — check meters are topic-fitting and options never contradict recorded history.

## 11. Out of scope (v1)

- Live LLM judging of free-text answers (v2 — M3 live tier)
- Student-device voting in class mode (v2)
- Scanning the printed answer sheet back in (v2, reuses paper-import)
- True story divergence / counterfactual branches (never — by design)
- Per-student inventories or persistent campaign across lessons (v3 idea: class "campaign map")

## 12. Build shape (preview)

1. **Phase 1 — digital core** (schema + spine + prompt + player meters + multi-branch): playable spel-verhaal without print pack.
2. **Phase 2 — print pack** (dompdf, templates, GenerateGamePack, download UI).
3. **Phase 3 — class mode polish** (team turns banner, game-over theatrics, projection layout).
